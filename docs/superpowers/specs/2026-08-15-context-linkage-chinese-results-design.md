# 病人背景連動與中文結果頁設計

## 目標

將病房與入院原因／診斷改為結構化下拉選單，讓可明確判定的病人背景自動連動主要臨床路徑或特殊因子，同時保留臨床人員處理多重共病的人工選擇能力。臨床結果與營養照護組合頁的可見內容統一使用中文，且處置優先度 `RED` 必須以紅字呈現。

## 病房選項與 ICU 連動

病房下拉選項為：

- 一般病房
- 加護病房 ICU
- 透析病房
- 其他

選擇「加護病房 ICU」時，自動啟用 ICU 主要臨床路徑。從其他病房切換至 ICU 時，不清除其他已選路徑或特殊因子。若病房仍為 ICU 而使用者手動取消 ICU 路徑，資料檢核區顯示不一致提醒；再次啟用 ICU 路徑時提醒消失。

## 診斷選項與臨床連動

入院原因／診斷下拉選項為：

- 一般內科／營養評估
- 重症／敗血症
- 腎臟病／透析
- 肝硬化／肝病
- 活動性癌症
- 高齡衰弱
- 心衰竭
- 吞嚥障礙
- 手術／術後
- 其他

診斷選擇的自動連動規則：

| 診斷 | 自動啟用 |
| --- | --- |
| 重症／敗血症 | ICU 主要路徑 |
| 腎臟病／透析 | RENAL 主要路徑 |
| 肝硬化／肝病 | LIVER 主要路徑 |
| 活動性癌症 | ONCOLOGY 主要路徑 |
| 高齡衰弱 | GERIATRIC 主要路徑 |
| 心衰竭 | heart failure 特殊因子 |
| 吞嚥障礙 | dysphagia 特殊因子 |

切換診斷時不自動移除先前已啟用的其他路徑或特殊因子，以支援多重共病。若使用者手動取消目前診斷直接對應的路徑或特殊因子，資料檢核區顯示不一致提醒。一般內科、手術／術後與其他不會自動選取主要路徑，仍由使用者依臨床判斷選擇 general adult 或其他路徑。

## 結果頁中文化

「臨床結果與營養照護組合」頁的標題、欄位名稱、狀態說明、安全警示、照護組合、監測項目與文件摘要均以中文顯示。內部資料模型繼續使用既有穩定代碼，例如 `RED`、`UNKNOWN`、`TOOL_SCORE_PENDING`，由顯示層轉換為中文，避免改動臨床判斷與正規化邏輯。

處置優先度顯示採以下對應：

- `RED`：紅色
- `AMBER`：琥珀色
- `GREEN`：綠色
- `GRAY`：灰色

當值為 `RED` 時，結果卡的主要數值文字必須使用高對比紅字；不能只靠邊框或背景色表示。

## 資料流與錯誤處理

背景下拉選單透過單一更新函式寫入 context，並在同一次狀態更新中啟用對應路徑或特殊因子。資料不一致由純邏輯函式產生 warning，不阻擋後續流程，避免覆蓋臨床人員的專業判斷。既有成人年齡、身高、體重、飲食狀態、NPO 與腎臟治療型態 blocker 維持不變。

## 驗證

- 單元測試涵蓋病房與 ICU 路徑連動、診斷對應路徑／特殊因子及不一致提醒。
- 瀏覽器測試確認病房與診斷均為下拉選單，選擇 ICU 與各診斷後對應按鈕呈啟用狀態。
- 結果頁檢查所有主要區塊使用中文，且 `RED` 處置優先度的文字計算樣式為紅色。
- 桌面與手機畫面不得出現水平溢位或文字重疊。

## 非本次範圍

- 不新增疾病編碼、院內 HIS 串接或病房主檔管理。
- 不改變正式量表原始計分規則。
- 不以診斷選項自動產生營養風險或營養不良診斷。
